# Topic 24 — Production Troubleshooting and Incident Response

**Status: Not started**

## Syllabus
- PostgreSQL service startup failures.
- Connection exhaustion and authentication failures.
- Slow queries, locks and deadlocks.
- Disk-full, WAL and archive issues.
- Replication lag and standby failure.
- Backup/restore and recovery incidents.
- Root-cause analysis and prevention.

## Standard incident workflow
1. Confirm impact and scope.
2. Preserve evidence and check recent changes.
3. Assess service, host, storage and database health.
4. Identify the immediate cause using read-only diagnostics first.
5. Select the lowest-risk remediation.
6. Validate service recovery and application behaviour.
7. Record root cause, prevention and follow-up actions.
